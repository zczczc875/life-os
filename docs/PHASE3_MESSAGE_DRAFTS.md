# Phase 3：从通知导入任务

Phase 3 的第一步是让用户把一条通知转成可以保存、完成并在重启后查看的任务。通知从桌面窗口手动粘贴，解析和保存均在本机完成。

## 使用方式

1. 点击「从通知导入」，粘贴通知后点击「生成草稿」。
2. 每个非空文本行可生成一条候选草稿。选中草稿后可以修改标题和日期，日期允许留空。
3. 点击「保存选中任务」后才写入数据库。保存成功的草稿从列表移除并刷新主界面；失败时草稿留在窗口中。重新生成会替换未保存草稿；关闭窗口会丢弃未保存内容。

支持 `交报告 DDL: 2026-12-18`、`交报名表，截止：2026-12-20。` 和 `请在 2026-12-18 前提交报告`。日期要求为真实的 `YYYY-MM-DD`。同一行有多个匹配时、日期无效、出现具体时刻或使用「下周五」这类相对时间时，核对草稿后可以手动填写日期。导入仅按文本行提取候选，不判断一行是不是真正的任务。

## 接口与迁移

- `LLMProvider.extract_tasks(message)` 仍返回草稿；`ExtractedTask` 增加可选的 `due_on: date | None`。桌面入口注入本地解析器，现有 Mock 的行为保持不变。
- `TaskService.create_task(title, *, due_on=None)` 扩展可选日历日期；列表与完成操作保留日期。日期不代表某个时刻，也不做时区转换。
- 新迁移 `0003_task_due_on` 增加可空列；已有任务的截止日期留空。源码更新后执行 `python -m alembic upgrade head`；Windows 打包版沿用确认与备份流程。
- 只保存确认后的标题和日期，输入区内容和未确认的草稿不单独写入数据库或日志。

## 任务列表的到期提示

未完成任务按本机日历日期显示「今天到期」或「已逾期」。已完成任务只显示原截止日期。程序打开时每分钟检查日期，跨日后会刷新列表。

## 验证

在 Windows 11 和 Python 3.12 上，167 项 pytest 测试通过，Ruff 检查与格式检查通过。测试覆盖通知导入、旧任务迁移、截止日期保存、任务完成后去除提示，以及跨日刷新和读取失败后的重试。
